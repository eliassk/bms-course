Chapter 15

Security systems

Intrusion alarms, access control, barriers and video. How each one works inside, which standards grade it, and how to connect it to a BMS without weakening it.

15.1 Intrusion alarm: zones, detectors, arming

An intrusion and hold-up alarm system (I&HAS) has four parts: a control panel (the CIE, control and indicating equipment), detectors, keypads or other set/unset devices, and warning and signalling devices: sirens, strobes and a communicator that reports to an alarm receiving centre (ARC). The panel has its own battery. It is a self-contained system that keeps working with every network in the building down.

Detectors

DetectorPrincipleTypical useWeak spot
Magnetic contactReed switch held by a magnet. Opens when the door moves.Doors, windows, hatchesDefeated by a second magnet unless high-security (balanced) type.

Higher-grade detectors add anti-masking: an active IR or microwave check that sees spray or tape over the lens and reports a fault while the system is unset.

Zones and zone types

Each detector is wired (or radio-enrolled) as a zone. The zone type decides how the panel reacts. The names differ by vendor; the behaviour is common:

TypeBehaviour
Entry/exitThe front door. Starts an entry timer (e.g. 30 s) instead of an instant alarm.
Follower (access)The hall PIR on the route to the keypad. Instant, unless an entry timer is running.
InstantAny other room or window. Alarm at once when set.
24-hourAlways active, set or not: tamper, safe, server room door.
Hold-up / panicAlways active, often silent, goes straight to the ARC.
TechnicalWater, freezer, gas. Reported, but not an intrusion.

Partitions (areas) let one panel run several independent alarms: shop and flat, office floors, tenants. Part set (stay/night) arms only the perimeter while people are inside.

How a panel reads a zone: end-of-line resistors

A simple loop would read only "closed" or "open". A cut wire would look like a closed door's opposite and a shorted wire would hide every future alarm. So the panel measures resistance. With double end-of-line (DEOL) wiring, typical values are a 4.7 kΩ resistor for normal and a second 4.7 kΩ that adds in series when the alarm contact opens. The panel now tells four states apart. Values vary by panel (1 k, 2.2 k, 4.7 k, 5.6 k are all common), so always use the ones in the installation manual.

Try it: arm a small office

A small shop uses a panel with eight wired zones and a 4G/IP dual-path communicator. Front door = entry/exit with 30 s entry and 45 s exit time. Hall PIR = follower. Stockroom PIR and windows = instant. Panic button under the counter = 24-hour silent hold-up. Night part set arms only the door and windows for the owner living upstairs.
Long entry delays are a classic weakness. An intruder has the whole delay to find and smash the keypad. Keep entry time short, mount the panel away from the keypad, and if possible use a system that reports an alarm when the entry time expires even if the keypad was destroyed.

The system is set. Someone walks in through the front door and then past the hall PIR. Why is the PIR not an instant alarm?

  • Panel, detectors, keypads, sirens and communicator; own battery, self-contained.
  • Zone type decides the reaction: entry/exit, follower, instant, 24-hour, hold-up.
  • EOL resistors let the panel tell normal, alarm, cut and short apart.

15.2 Grade standards (EN 50131)

In Europe the EN 50131 series defines intrusion and hold-up alarm systems. Its core idea is the security grade: 1 to 4, chosen from a risk assessment of who is likely to attack and how much they know. Every component in a system must be at least the system's grade; the system takes the grade of its lowest component. Insurers often require a grade in the policy.

GradeExpected intruderTypical premisesNotable requirements
1Little knowledge, few toolsLow-risk domesticBasic tamper detection. Rarely accepted by insurers.
2Some knowledge, common tools (e.g. a screwdriver)Most homes, small offices and shopsTamper on lids and loops, event log, user codes with at least ~10,000 combinations.
3Experienced, knows alarm systems, portable toolsShops with valuable stock, commercial sites, pharmaciesAnti-masking on detectors, monitored signalling path, tighter tamper and log requirements.
4Organised, plans the attack, specialist equipmentBanks, vaults, high-risk sitesHighest anti-masking, redundant monitored paths, extensive logging.

Other parts of the standard

  • Environmental class I–IV: indoor heated, indoor general, outdoor sheltered, outdoor general.
  • EN 50131-1: system requirements. -2-x: detectors. -3: control panel. -4: warning devices. -6: power supplies. -7: application guidelines.
  • EN 50136: alarm transmission systems (ATS), graded SP1–SP6 (single path) and DP1–DP4 (dual path) by how fast a failed path is detected.
  • Standby battery: grade and notification type set the hours (commonly 12 h or more, more if no ARC monitors it).

Other regions use other schemes, for example UL 2050 / UL 681 in the US, and national police or insurer rules (VdS in Germany, NSI/SSAIB certification in the UK) on top of EN 50131.

A jeweller's insurer demands grade 3. The installer picks grade 3 detectors with anti-masking, a grade 3 panel and a dual-path communicator (IP plus 4G) to an ARC. One cheap grade 2 wireless contact on a back window would drop the whole system to grade 2.
"Grade 3 panel" on a datasheet does not make a grade 3 system. The grade belongs to the installed system: lowest component, correct configuration, correct signalling.

A system has a grade 3 panel, grade 3 PIRs and one grade 2 door contact. What is the system grade?

  • Grades 1–4 follow the expected attacker's skill and tools.
  • System grade = lowest component grade.
  • EN 50136 grades the signalling path to the ARC separately.

15.3 Access control: readers, controllers, credentials

Access control answers one question at every door: may this person pass here, now? The parts:

  • Credential: card, fob, phone, PIN or biometric.
  • Reader: reads the credential and sends an ID to the controller.
  • Door controller: holds the access rules and the cardholder database locally, drives the lock, reads the door contact and the request-to-exit (REX).
  • Lock: electric strike, magnetic lock, motorised lock or electronic cylinder.
  • Server: enrols people, defines groups and schedules, collects events. Doors MUST keep working if it is offline.

The door is a state machine

A controller tracks each door with two inputs (door position contact, REX) and one output (lock relay). From these it derives states such as forced open (door opened without a grant) and held open (door left open after the shunt time, e.g. 30 s). Step through it.

Fail-safe and fail-secure

A fail-safe lock unlocks when power is lost (a maglock: no power, no hold). A fail-secure lock stays locked (most strikes can be ordered either way). Doors on an escape route must let people out at all times: mechanical free egress by the handle, or a fail-safe lock released by the fire alarm and an emergency break-glass. Local fire and building codes decide; in Europe EN 179, EN 1125 and EN 13637 cover exit hardware and electrically controlled exit systems.

Reader to controller: Wiegand and OSDP

The classic Wiegand interface sends the card number one way over two data wires. The common 26-bit format is 1 parity bit, 8-bit facility code, 16-bit card number, 1 parity bit: only 65,535 card numbers per facility. It has no encryption and no supervision, so a small device on the wires can record and replay cards. OSDP (Open Supervised Device Protocol, IEC 60839-11-5) runs over RS-485, is bidirectional, supervises the reader and, with Secure Channel, encrypts the link with AES-128.

An office replaces 125 kHz cards with DESFire EV3 cards carrying a site key, and swaps Wiegand readers for OSDP readers with Secure Channel. The controller now raises an alarm if a reader is unplugged, and a sniffer on the cable sees only ciphertext.
Many "secure" cards are read only by their UID (serial number). A UID is not a secret and can be emulated. Make sure the reader authenticates against an application key on the card.

The door contact opens but the controller issued no grant and no REX. What event?

  • Controllers decide locally; the server only manages and logs.
  • Door contact + REX + lock give granted, forced and held-open states.
  • Prefer DESFire/Seos-class cards with site keys, and OSDP Secure Channel over Wiegand.

15.4 Barriers and gates

Barriers, sliding gates, swing gates, bollards and turnstiles are access control points with a motor. That motor can hurt people, so the safety design matters as much as the access logic.

Vehicle detection

An inductive loop is a few turns of wire cut into the road surface. A loop detector drives it at roughly 20–150 kHz; a car's metal lowers the inductance and shifts the frequency. Typical layout:

  • Arming / presence loop before the barrier: the reader only accepts a card when a vehicle is there.
  • Safety loop under the boom: the boom MUST NOT close while it is occupied.
  • Closing loop after the barrier: close once the vehicle has left it.

Other inputs: ANPR cameras (number plates), long-range UHF tags, radar and photocells.

Safety standards

In Europe powered gates fall under the Machinery Directive (moving to the Machinery Regulation 2023/1230) and the product standard EN 13241, with EN 12453 setting safety in use. The approach is risk based: limit the force (EN 12453 sets dynamic force limits, such as around 400 N in some zones, measured with a force gauge), or add safety edges and photocells, or both. Results are recorded at commissioning and re-tested at maintenance. Turnstiles and speed gates have their own product rules.

A car park barrier has a 3 m boom, a card reader on a pedestal, three loops and a photocell. The parking system opens it on a valid card or ANPR match. A fire alarm input raises all boom gates so emergency vehicles and leaving cars are not blocked.
Never let a BMS or remote panel "close" a gate without local safety devices in the loop. A remote close command MUST still be subject to the safety loop, photocells and force limits in the gate controller itself.

A car stops under the boom. What prevents the barrier closing on it?

  • Loops detect metal by frequency shift: arming, safety, closing.
  • Gate safety (force limits, edges, photocells) lives in the gate controller.
  • Fire alarm opens barriers on egress routes.

15.5 CCTV: IP cameras, ONVIF, RTSP, NVR

Modern CCTV is IP video. A camera contains an image sensor, an encoder (H.264 or H.265), a small Linux system and a web server. It is powered by PoE: 802.3af gives up to 15.4 W at the switch port, 802.3at 30 W for PTZ and heaters. Recording happens on an NVR (network video recorder) or a VMS (video management software) on a server.

The protocols

LayerProtocolJob
Discovery and controlONVIF (SOAP over HTTP, WS-Discovery)Find cameras, read profiles, get stream URLs, move PTZ, subscribe to events.
Session controlRTSP (TCP 554)DESCRIBE, SETUP, PLAY, TEARDOWN a stream, like a remote control.
Session descriptionSDPLists the tracks: video H.264, audio AAC, payload types.
Media transportRTP / RTCP (UDP, or interleaved in the RTSP TCP connection)Carries the compressed frames with timestamps.
Browser viewingWebRTC, HLS, MJPEGConverted by the VMS or a gateway (e.g. go2rtc).

ONVIF profiles define what a conformant device supports: Profile S (streaming), G (edge recording), T (H.265, imaging, events), M (analytics metadata). "ONVIF compliant" without a listed profile means little.

A typical stream URL looks like rtsp://192.0.2.31:554/Streaming/Channels/101 (main stream) and …/102 (sub stream). The path is vendor specific; ONVIF GetStreamUri returns the correct one. Cameras usually offer a high-resolution main stream for recording and a low-resolution sub stream for live grids and analytics.

Bitrate and storage

Storage is simple arithmetic: bitrate × time × cameras. A 4 MP H.265 camera at 15 fps often runs 2–4 Mbit/s with normal motion; the same in H.264 needs roughly 1.5–2× more. Scenes with trees, rain or night noise raise bitrate sharply. Use the calculator.

A school records 40 cameras at 4 Mbit/s for 30 days, continuously: 40 × 4 Mbit/s = 160 Mbit/s = 20 MB/s, about 1.73 TB per day, about 52 TB for 30 days. With RAID 6 on 8 TB drives this is nine or ten drives. Many sites cut this by half with motion- or event-based recording and lower night bitrate.
Cameras ship with web interfaces, cloud "P2P" services and sometimes old firmware with known vulnerabilities. Put them on their own VLAN, block internet access, disable UPnP and P2P, change default passwords and update firmware. Retention is also a legal limit under privacy law: keep footage no longer than the stated purpose needs.

Which protocol tells the VMS the correct RTSP URL of a camera's main stream?

  • ONVIF finds and configures; RTSP sets up; RTP carries the video.
  • Storage = bitrate × seconds × cameras; codec and scene dominate bitrate.
  • Cameras go on an isolated VLAN with no internet access.

15.6 Video analytics

Video analytics turns pixels into events. Classic analytics used motion detection: compare frames, count changed pixels. It triggers on rain, shadows and headlights. Modern analytics run neural networks that detect and classify objects (person, vehicle, bicycle) and track them across frames. Rules then sit on top of the tracks.

RuleExample
Line crossingA person crosses the fence line from outside to inside.
Intrusion / areaA vehicle is in the loading bay for more than 10 s after 22:00.
LoiteringA person stays near an ATM for more than 3 min.
Counting / occupancyPeople in and out of a shop entrance, feeding occupancy to the BMS.
ANPR / LPRNumber plate read at a car park barrier.
Left object, crowd, fallMore specialist, with more false alarms.

Analytics can run at the edge (in the camera's own chip) or on a server (GPU, VMS plug-in). Edge scales with camera count and sends only metadata; server analytics are more flexible. ONVIF Profile M standardises how analytics metadata and events are delivered.

Try it: the confidence threshold trade-off

Each detection comes with a confidence score. The threshold decides which ones raise an event. Low threshold: every intruder is caught, but so are cats and swaying bushes. High threshold: quiet, but some people are missed.

A logistics yard monitored by an ARC used motion detection and saw hundreds of false alarms per night. After switching to person and vehicle classification with a line-crossing rule on the fence, false alarms dropped to a handful, and operators started trusting alarms again.
Face recognition and other biometric analytics are heavily regulated. In the EU, GDPR treats biometric data as a special category, and the AI Act restricts real-time remote biometric identification in public spaces. Check the legal basis before enabling it.

An ARC complains about too many false alarms from foxes. What is the first fix?

  • Object detection + tracking + rules beats pixel motion detection.
  • The threshold trades missed events against false alarms.
  • Edge analytics send only metadata; ONVIF Profile M standardises it.

15.7 Integrating security with BMS safely

A BMS gains a lot from security data: an unset alarm area means people are present, so heating and lighting can follow. A door badge can wake a meeting room. A camera people-count can drive ventilation. The risk is the opposite direction: a compromised or buggy BMS that can unset an alarm or unlock a door has become part of the security system, without its certification.

Interface options

  • Dry contacts: panel relay outputs "area A set", "alarm", "fault" into BMS digital inputs. Simple, one-way, very robust.
  • Vendor SDK / API: many panels and access systems have an IP integration module or REST/SDK. Use a dedicated low-privilege account.
  • BACnet / Modbus / OPC UA gateways offered by the security vendor, ideally with commands disabled.
  • ONVIF events / VMS API for video: motion, analytics, camera offline.
  • Fire alarm interface: hard-wired, certified release of escape doors, independent of BMS software.

Rules of thumb

  1. Default to read-only. Security status out, no commands in.
  2. If a command is needed (open the visitor gate, unlock a meeting room during a booked slot), allow only that point, log it with a named user, and let the security system enforce its own rules.
  3. Never unset an intrusion area from the BMS without a user code entered by a person.
  4. Separate networks: security VLAN, firewall rules that permit only the integration host and port.
  5. The security system MUST keep working if the BMS and the integration fail.

Sort these integrations

Alarm area "set" drives the HVAC unoccupied mode.
A dashboard button unsets the intrusion alarm without a code.
Panel mains failure and battery fault show in the BMS alarm list.
The BMS unlocks escape doors in a fire via a script.
Reception staff open the visitor gate via the access API, logged per user.
Camera web pages are port-forwarded so the BMS cloud can show them.
An office building wires three relay outputs from the intrusion panel (floors 1–3 set) into the BMS. When a floor is set, the BMS drops it to unoccupied setpoints and switches off lighting. When unset, comfort mode starts. The BMS has no path to send anything back to the panel.
Convenience creeps. "Just one button to arm from the panel" soon becomes "and disarm", then "remotely". Each step moves security decisions into a system that was never graded or tested for them.

Which integration is safest for driving HVAC from intrusion status?

  • Status out, commands stay in the security system.
  • Any command allowed: single point, named user, logged.
  • Escape door release is hard-wired to fire, never BMS logic.
