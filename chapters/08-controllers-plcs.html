Chapter 08

Controllers and PLCs

The boxes in the panel that actually run the plant. How a controller executes its program, how it is wired to sensors and actuators, how it is programmed, and why it must keep working when everything above it fails.

8.1 DDC controllers vs. PLCs

Two families of controllers run buildings. A DDC controller (Direct Digital Control) is made for HVAC. A PLC (Programmable Logic Controller) comes from factory automation. Inside, both are a small real-time computer with I/O. The difference is in what they are optimised for, how they are programmed and which protocols they speak out of the box.

"Direct digital" was a contrast to the pneumatic and analogue electronic controllers of the 1970s. Instead of a bellows or an op-amp circuit computing the valve position, a microprocessor samples the sensor, runs a PID algorithm in software and writes an output. Every modern building controller is "DDC" in that sense. Today the term means a controller sold into building automation, with HVAC libraries and a building protocol, usually BACnet.

The cyclic program

Both run their logic in a loop called the scan or cycle:

  1. Read inputs. All physical inputs are copied into an input image in memory.
  2. Execute. The program runs top to bottom using only that image. Inputs do not change mid-scan.
  3. Write outputs. The output image is copied to the physical outputs.
  4. Housekeeping. Communication, diagnostics, the watchdog reset.

A PLC scan is typically 1 to 20 ms. A DDC controller often runs its HVAC programs every 100 ms to 1 s, since a room temperature changes in minutes. The consequence: any input pulse shorter than one scan can be missed, unless the input module latches it or counts it in hardware.

Since the scan is cyclic, a program never "waits". A delay is a timer block that is checked each scan. A controller that hangs in a loop would stop updating outputs, so a hardware watchdog resets or stops the CPU if a scan exceeds a limit (often 100–500 ms on PLCs), and outputs go to a defined safe state.

The lines blur. Many building controllers are programmable in IEC 61131-3 (for example those built on the CODESYS runtime), and PLCs from Siemens, Beckhoff or WAGO have BACnet libraries. The real decision is usually about the protocol at the top and the engineering tools the integrator knows.

A large AHU with heat recovery, two fans and frost protection is controlled by a DDC controller with a vendor AHU template: about 40 points, configured in a day, BACnet objects for every point appear automatically. The same building's sprinkler pump room or a stage machinery system uses a PLC, because it needs millisecond response, safety functions and a PROFINET drive bus.
Office floor heating and ventilation that must appear as BACnet objects in the BMS.
A conveyor with 12 drives on PROFINET and 5 ms response to light curtains.
A boiler room with weather-compensated flow temperature and a holiday calendar.
A theatre fly system with motion interlocks and position encoders.

A flow meter sends 20 ms pulses. The controller scans every 100 ms on a normal DI. What happens?

  • Both execute a cyclic scan: read inputs, execute, write outputs.
  • Pulses shorter than a scan need hardware counters or latching inputs.
  • DDC = HVAC libraries and BACnet built in. PLC = fast, general purpose, industrial fieldbus.

8.2 Siemens building controllers

Siemens is one of the largest building automation vendors, next to Honeywell, Johnson Controls, Schneider Electric, Distech, Sauter and others. Its range is a good case study, because it shows the typical layers every vendor offers: a management platform, automation stations, room controllers, I/O and OEM unit controllers. The names change over the years. The structure does not.

Engineering workflow

A typical project with a vendor's building controllers runs like this:

  1. Points list. Every sensor and actuator with its type, range and name.
  2. Choose templates. The vendor library has applications for an AHU, a heating circuit, a room. You select options (heat recovery: plate or wheel; humidifier: yes or no).
  3. Assign I/O. The tool maps logical points to terminals and prints wiring diagrams.
  4. Download and commission. Load the program, check each point (point-to-point test), tune loops.
  5. Hand over to the BMS. BACnet objects are discovered or imported by the management station.
Engineering tools are usually licensed and tied to the vendor's partner network. A building owner can be locked into one integrator for every change. Ask at tender stage for the project files, the tool version and a licence path, and keep backups of every controller program.
A hospital wing has 14 PXC-class plant controllers and about 300 room controllers. The management station shows 25 000 BACnet objects. When the management server is replaced by another vendor's platform ten years later, the controllers stay, because they are plain BACnet devices.

A packaged rooftop unit arrives with an OEM controller that exposes Modbus. What is its usual role?

  • Vendor ranges follow one shape: management, plant controllers, room controllers, I/O, OEM controllers.
  • Templates make HVAC engineering fast, but tools and licences can lock owners in.
  • Open protocols at the controller level let the management layer be replaced independently.

8.3 IEC 61131-3 programming basics

IEC 61131-3 is the international standard for PLC programming languages. It defines data types, variables, program organisation units and five languages. The third edition (2013) added object-oriented features and marked Instruction List as deprecated.

LanguageStyleGood for
LD Ladder DiagramGraphical, relay contacts and coilsInterlocks, simple Boolean logic, electricians reading it
FBD Function Block DiagramGraphical, blocks wired togetherControl loops, signal flow, most HVAC programs
ST Structured TextTextual, Pascal-likeCalculations, loops, arrays, anything algorithmic
SFC Sequential Function ChartSteps and transitionsSequences: start-up, defrost, boiler cascade
IL Instruction ListAssembly-likeLegacy only (deprecated)

Program organisation units

  • Function (FUN). No memory. Same inputs give the same output. ADD, LIMIT, SEL.
  • Function block (FB). Has internal state, used as an instance. TON timer, CTU counter, R_TRIG edge detector, a PID block. Each instance has its own memory, like an object.
  • Program (PRG). The top level, assigned to a task that runs cyclically, for example every 10 ms or every 1 s.

Try it: a motor start/stop with seal-in

The classic first program. A Start push button starts a fan. It keeps running after you let go, because its own run contact "seals in" the rung. Stop (wired normally closed) or an overload trip stops it. Toggle the inputs and watch the scan evaluate the rungs.

Standard timers

BlockBehaviourHVAC use
TONOutput goes TRUE after IN has been TRUE for PTProve airflow 30 s after fan start; alarm delay
TOFOutput stays TRUE for PT after IN goes FALSEPump overrun after boiler stops; fan run-on after electric heater
TPFixed-length pulse on rising edgeA 2 s reset pulse to a drive

Structured Text is closest to what a software developer knows. A small heating curve function:

FUNCTION HeatingCurve : REAL
VAR_INPUT
  tOutside : REAL;  // °C
  slope    : REAL := 1.4;
  tRoom    : REAL := 20.0;
END_VAR
HeatingCurve := LIMIT(25.0, tRoom + slope * (tRoom - tOutside), 75.0);
END_FUNCTION

At −10 °C outside this gives 20 + 1.4 × 30 = 62 °C flow temperature. Real heating curves are often slightly curved, but the structure is the same.

Every graphical language compiles to the same scan. Order matters: if rung 5 reads a value that rung 9 writes, rung 5 sees last scan's value. In FBD, check the execution order numbers the tool shows on each block. Many hard-to-find bugs are one-scan delays or a variable written in two places.
CODESYS is a vendor-neutral IEC 61131-3 runtime and IDE used by hundreds of hardware makers, including several building controller brands. A developer who knows it can program controllers from WAGO, Beckhoff (TwinCAT is built on similar concepts), Eaton and many others.

A fan must keep running 3 minutes after an electric heater switches off. Which block?

  • Five languages, one execution model. FBD dominates HVAC, ST suits calculations, SFC suits sequences.
  • Function blocks have memory; each instance is like an object.
  • Execution order inside the scan creates one-scan delays. Watch it.

8.4 I/O modules and wiring

Every physical point is one of four types. Chapter 1 introduced them; here is what happens electrically.

TypeCommon signalsExamples
AI analogue inputPt1000, NTC 10k, Ni1000, 0–10 V, 4–20 mATemperature, pressure, humidity, CO₂
AO analogue output0–10 V (or 2–10 V), 4–20 mAValve actuator, fan speed to a VFD
DI digital inputDry contact, 24 V DC, pulsePump status, filter alarm, energy meter pulses
DO digital outputRelay contact, 24 V AC triacPump start, 3-point valve open/close

Analogue scaling

The controller measures a raw electrical value and scales it linearly to an engineering value. For a 4–20 mA pressure transmitter with range 0–10 bar: p = (I − 4) / 16 × 10. 12 mA means 5 bar. The "live zero" at 4 mA is the point: 0 mA means a broken wire, not zero pressure. The NAMUR NE43 recommendation treats values below about 3.6 mA or above 21 mA as a fault. A 0–10 V signal has no live zero, so 0 V could be a broken wire or a real zero.

A Pt1000 is a resistor: 1000 Ω at 0 °C, about 3.85 Ω per kelvin. At 21 °C it reads about 1081 Ω. An open circuit reads infinite, a short reads 0 Ω; good controllers flag both.

Universal I/O and practical wiring

  • Universal inputs/outputs (UI/UIO). One terminal configurable as AI, DI or AO in software. Common on building controllers. Flexible during commissioning, but check per-terminal limits.
  • Common reference. Many AIs share one ground "M". A 24 VAC actuator sharing that ground with a sensor can shift readings by tenths of a degree if wiring is long or the ground wire is shared. Run separate signal grounds.
  • Shielding. Use shielded cable for analogue signals near VFDs and earth the shield at one end only.
  • Relay ratings. A 2 A relay must not switch a pump motor directly. Switch a contactor coil.
  • Hand/Off/Auto. Many panels have override switches per output, with the switch position fed back as a DI so the BMS knows someone overrode it.
A 10k NTC and a Pt1000 look identical on a cable label. Configure the wrong type and a room reads, for example, 60 °C or −40 °C. During point-to-point testing, warm every sensor in your hand and watch the value move.
A supply air duct sensor reads 0.8 K high. Cause: 60 m of 0.5 mm² cable on a 2-wire Pt1000. Loop resistance is about 2.1 Ω, which a Pt1000 reads as roughly 0.55 K, plus a shared ground with an actuator. Options: a cable offset correction in the controller, a 4-wire connection, or a transmitter with 4–20 mA.

A 4–20 mA, 0–50 °C transmitter reads 2.1 mA. What should the controller report?

  • AI, AO, DI, DO. Each has a typical electrical signal and limits.
  • 4–20 mA has a live zero: below ~3.6 mA is a fault, not a value.
  • Grounds, shielding and cable resistance cause most "wrong value" problems.

8.5 Local autonomy when the BMS is down

A good architecture follows one rule: control runs in the lowest layer that has all the data it needs. A heating loop's sensor, PID and valve sit on one controller. The BMS server only sets the setpoint and reads the result. If the server dies, the loop keeps the last setpoint and keeps controlling.

This is called local autonomy or stand-alone operation. EN ISO 16484 and typical specifications require that each automation station runs its plant without the management level. Some go further: a room controller must run its room even without the plant controller.

What must live where

FunctionMust be local?Why
PID loops, safeties, frost protectionYesSeconds matter; no network in the path
Time schedulesYes, a copyThe building must still go to night mode
Trend bufferYes, a ring bufferUpload later; no gap in history
Alarm detectionYesDelivery may be delayed, detection must not be
Optimisation across systemsNoLose it, and the plant falls back to local defaults
Dashboards, reports, notificationsNoManagement level by nature

Try it: break things

Design for failure

  • Fallback values. Every value received over the network has a timeout and a default. If the outdoor temperature from another controller is older than, say, 10 minutes, use a fixed value like 0 °C.
  • Output fail states. What does the output do if the controller dies? A spring-return actuator closes an outdoor-air damper; a heating valve may be specified to fail open to prevent freezing.
  • Hardwired safety. Frost thermostats, fire dampers and high-limit thermostats act on the hardware directly, not only through software.
  • Commands with priority. In BACnet, writes go to a priority array. If the BMS dies, its last command at priority 8 stays. A relinquish default defines what happens when all commands are released.
  • Battery and clock. After a power cut the controller needs the right time for schedules. A buffered RTC and NTP or BACnet time sync on reconnect.
A common anti-pattern: a dashboard or home-grown integration server runs the control loop itself, reading a sensor and writing a valve every few seconds over the network. It works until the server reboots for updates at 3 am in January. Keep loops in controllers.
During a 6-hour BMS server outage after a failed update, a school's heating plant ran normally: the boiler controller had the schedule and weather compensation locally. The only loss was the alarm notifications and 6 hours of trend data on the server, which the controllers' trend buffers filled in afterwards.

Controller A uses an outdoor temperature read over BACnet from controller B. B goes offline. What is the right behaviour?

  • Control runs at the lowest level that has its data. The BMS supervises.
  • Every network value needs a timeout and a fallback.
  • Define fail states for outputs and keep safeties hardwired.

8.6 Room controllers and thermostats

The room is where users feel the building. A room controller reads room temperature (and often CO₂, presence, window contacts), and drives a radiator valve, an underfloor manifold actuator, a fan coil or a VAV box. A thermostat is the simplest kind: on/off with a switching difference.

Operating modes

Rooms do not have one setpoint. They have a mode, set by schedule, presence or the user. The names come from the European standards and KNX:

ModeTypical heating setpointTypical cooling setpointWhen
Comfort21 °C24 °COccupied
Pre-comfort / Standby19 °C26 °CScheduled but nobody present
Economy16–17 °C28 °CNight, weekend
Building protection5–8 °C35 °CWindow open, long absence

A window contact typically forces protection mode, so heating does not fight an open window.

On/off vs PI control

An on/off thermostat turns heat on below setpoint − hysteresis/2 and off above setpoint + hysteresis/2. With a slow radiator, the room overshoots. A PI room controller instead modulates a valve or uses pulse width modulation on a thermal actuator: for example a 10-minute cycle, valve open 3 minutes = 30 %. The result is a flatter temperature.

Kinds of room devices

  • Standalone thermostat. Switch, setpoint knob, on/off output. No network. Cheap.
  • Communicating thermostat. Same, plus Modbus, KNX or BACnet MS/TP, so the BMS can set mode and read temperature.
  • Room controller with room unit. Logic in a controller in the ceiling or a cabinet. The wall unit only senses and shows. Several rooms per controller is common.
  • Wireless radiator valve heads. Battery thermostatic heads on Zigbee, Z-Wave, EnOcean or proprietary radio. Common in retrofit.
Do not put the room sensor on an outside wall, in sunlight, above a radiator or next to a printer. A sensor 1 K wrong costs comfort for the whole room and about 6 % heating energy per kelvin of overheating (a common rule of thumb, varying with climate).
An office with underfloor heating used on/off thermostats with 0.5 K hysteresis. Because the slab responds over hours, rooms swung by ±1.5 K. Switching the thermal actuators to PWM with PI control and a 15-minute cycle reduced the swing to about ±0.3 K without new hardware.

A user opens a window in winter. What should a well-configured room controller do?

  • Rooms run in modes: comfort, pre-comfort, economy, protection.
  • On/off with slow emitters overshoots. PI with modulating or PWM output is flatter.
  • Sensor placement matters as much as the algorithm.
